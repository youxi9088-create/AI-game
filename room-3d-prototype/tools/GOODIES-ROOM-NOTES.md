# 第四间小屋：顾家 · 午后客厅

## 约束与实现

- 用户要求用 Goodies 资源新增房间，并列在原有三间旁边；不是替换原三间。
- 新房间 `goodies` 位于 x=21；原 forest=-10.5、kitchen=0、atelier=10.5 及原物件 ID 不变。
- 用户纠正：整间房屋的风格都使用 Goodies，不能只替换家具。第四间不再复用程序外壳、窗框、装饰画、墙色或程序木纹。使用59个 Goodies 原装建筑模块（含30块木地板、窗户、内外墙和斜切侧墙），全部保留导入材质；导航与房间外公共街道复用原实现。
- 室内 11 件物件使用 Goodies GLB 与对应原贴图：三人沙发、单椅、圆茶几、木边桌、书柜、地毯、落地灯、台灯、绿植、相框、平板。
- 家具保持统一比例缩放；桌面摆件按茶几/边桌实际模型高度落地，原网格参与放置射线，不添加过大隐形热区。
- 家具注册到已有移动/保存系统，ID 为 `goodies:*`；新增延迟注册入口，启动保存合并已有家具位置，避免网络加载期间删除新房间的旧存档。
- 街道向右延伸，总览重新居中；选中房间时阴影相机跟随房间，保留光照方向。
- 家具资源先全部取回再挂入房间。加载失败显示错误及刷新重试提示，原有三个房间仍可操作。
- 本地入口：`http://127.0.0.1:5175/?level=2&home=goodies`。未发布公网，第三方素材许可仍须上线前核对。

## 范围与验证

本次是阶段二真实资源应用的局部扩展，复用已存在的导航和摆放方式，没有重设计首页或推进阶段三 AI 生产服务。阶段一旧交互和阶段三 AI 生成均不能因本次构建通过而升级为已验证。

功能检查：`node tools/test-goodies-room.mjs` 通过。覆盖59个建筑模块、30块原木地板及摆放射线、11个家具模型及贴图引用、房间边界、3个桌面支撑接触、稳定 ID、旧/新房间位置恢复、延迟注册不丢存档、按房间隐藏及失败不提交半套家具。`npm run build` 通过。

界面状态：已实现待界面验证。浏览器工具先前被访问策略阻止，未绕过限制，未完成本轮截图、拖动与实际视觉验证。按 game-mvp-evidence-loop 的门禁，不能把上述非视觉检查称为玩家路径验收。

待实际界面复验：整条街同屏四间 → 点击顾家 → 检查家具朝向、材质及可读性 → 拖动单椅 → 移动圆茶几确认桌面物件跟随 → 刷新恢复 → 切回原三间检查原位置 → 第一关寻物回归。AI 新物件摆放复用原入口，但本轮未调用服务端模型生成。
