# 牌友视觉生产标准

牌友工坊生成的所有新资产都遵循这份标准，作为提示词、落盘校验和前端展示的共同合同。

## 当前 Provider 规则（2026-09-18）

- 除跳舞视频外，所有视觉资源统一使用 `aihub-asset-production`：角色资料卡使用 `gpt-image2`，其他图片使用 `jimeng`。
- 服务端只保存 AIHub 的 `runId`、状态、输出 URL 与落盘校验结果；不再从牌友工坊直连 AI Gateway。
- 入场与五态动作视频使用 AIHub `seedance` 能力；只有首套跳舞/换装演出视频使用指定的 AIHub 跳舞工作流；资料卡确认后，同一张资料卡公网 URL 注入所有图片与视频节点。
- 运行环境只需要 `AIHUB_AGENT_TOKEN`；角色资料卡、其他图片和非跳舞视频直接使用 skill 注册的 `gpt-image2`、`jimeng`、`seedance` 别名；只有首套跳舞视频节点另需 `PAL_DANCE_WORKFLOW_APP_ID`。

- 视觉语言：与林星保持同一套半写实电影级游戏 CG 制作语言（午夜蓝紫调、香槟金轮廓光、真实皮肤/发丝/布料、浅景深）；只继承画风，不复刻林星、银岚或其他角色的身份特征。
- 角色图：主立绘 3:4；牌桌立绘 4:5 半身；大厅主视觉使用半身英雄构图。需要抠像的资源必须是带真实 alpha 通道的 PNG，禁止白底、灰底、棋盘格或任何占位背景。
- 角色资料卡：创建牌友时从白名单选择服装（按文字描述、优雅女仆装、空姐制服风、现代改良旗袍、摩登赛车夹克、黑曜石晚宴礼服）与配饰（无、兔耳朵发饰、猫耳朵发饰、珍珠耳饰、丝带发饰）。选择会写入不可变的 `profileCard`，包含角色、五态动作、服装和配饰，并同时注入图片与视频提示词。
- 资料卡定位：角色资料卡是「包含多种素材的参考总图」（全身形象、头肩像、服装配饰细节、五态动作参考），只用于工坊预览、用户确认与后续生产参考；保留完整资料，绝不直接用于主页、牌桌或任何运行时展示槽。运行时每个位置（头像、大厅/牌桌立绘、五态单图、卡面、视频封面）都是独立文件；固定布局、边界清晰的源拼图按记录区域拆分并逐张验收，重叠/被裁切/尺寸不足的素材以资料卡为参考单独生成。每份资源的「角色、服装、用途、动作、来源、验收状态」账目见 `apps/api/data/official-assets.json` 与 `GET /api/assets/registry`。
- 资料卡门禁：工坊严格拆成两次提交——第一次只生成角色资料卡，并取得可由 Provider 访问的公网 `image_url`；用户确认资料卡后，第二次点击“继续生产”才提交下游。下游图片与视频节点都注入同一个已确认的角色资料卡 URL；舞蹈参考视频只控制节奏、镜头和动作质感，不改变资料卡中的角色、服装、配饰或画风。
- 图片路由：角色资料卡固定使用 AIHub `gpt-image2`；资料卡以外的图片固定使用 AIHub `jimeng`，统一遵循 `run → status → outputs`，不再直连 AI Gateway。入场/五态动作视频使用 AIHub `seedance`；只有首套跳舞/换装演出使用指定跳舞工作流。
- 资源绑定：写真馆只收录带有该套装自身 `cardVideo/cardPoster` 的资源；一张写真卡对应一段独立回放视频。`outfit-film` 必须以已完成的首套服装写真卡面公网 `image_url` 作为唯一角色与服装参考，视频参考只控制动作和镜头；卡面未生成、未成功或没有公网 URL 时明确阻断，绝不回退使用主立绘或角色默认舞片。没有视频的静态服装图只能作为牌桌表现或待生产资产，不能进入写真卡池。
- 视频静帧：`scripts/make-dance-assets.mjs` 从距视频结尾的安全窗口取帧，避免把人物出画或缺头的坏尾帧固化成 poster/frame。
- 交付边界：当前资料包不再区分 MVP 与完整包，所有新建计划统一为“完整首发包”。角色资料卡确认后，必须按完整资源清单继续生产角色五态、入场、首套换装/写真演出及其配套视觉；未齐全时保持 `ASSET_PENDING`，不得按静态包提前上桌。
- 名册与展示：新牌友必须有可编辑自然中文名；确认建档后归入写真馆“自定义牌友”分类；已经排入下一局的资产按钮显示“已排入牌局”并禁用。
