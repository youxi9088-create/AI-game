# DressBattle：主动玩法、音频与 3D 恢复记录

2026-10-04。恢复 2026-10-02 工作区清理前未推送的迭代；基于玩法优化方案 v1.5 和音频系统设计 v1.0。代码分批保存到现有草稿 PR #1，未部署 yyxx101.online。

## 当前实现

- 胜局 RESULT 主动选择本次牌友服装；选择未拥有服装解锁，选择已拥有服装升级。重复换选只保留一份奖励，不增发 Token/羁绊/等级。服务端限制最新胜局，演出后锁定，保存失败回滚。
- 演出快门、视频时间轴、三个取帧位置、滤镜、构图、标题、底色、鎏金工艺；角色羁绊 30 解锁棱彩。预览和 PNG 导出取自同一真实视频时刻，无视频时保留静态画面。背景目前为底色，尚非抠像换景；姿态取决于视频，尚非自由骨骼控制。
- 连续拖选、单张点击、出牌短动画、炸弹/顺子粒子，收藏卡悬停倾斜与光泽；轻量/关闭、系统减少动态兼容。
- Tone.js 15.1.22 自托管：18 类短音效、70 个原创程序生成样本变体，样本数据约 3.9 MiB。分总线音量、混响区域、-1 dB limiter、动态紧张度音乐、小节边界编排变换、视频音乐压低。13 音乐/环境声部预算 + 11 短音效上限；诊断明确为预算，不伪装 DSP 测量。尚无真实角色 VO、正式录音素材和完整 FMOD bank。
- Three.js 0.180.0 自托管：牌桌/灯光阴影/桌面卡牌是真实 WebGL 场景；2026-10-04 视觉返工后，房间改用项目现有绘制场景，撤下方块椅子与窗景原型；牌面来自服务端当前出牌。手牌操作保留 HTML 可访问控件，角色仍为原二维媒体。单 renderer 跨页面重绘复用、卡牌纹理替换释放、静止后停止渲染、隐藏暂停、WebGL 不可用或上下文丢失时回退标准牌桌。
- 入口：音量设置 → 牌桌渲染 → 3D 月夜会客厅（预览）。默认标准牌桌。
- 锁定 npm 依赖、保留 MIT 许可；`npm ci` / `npm run build` 重建本地 vendor；Docker 显式执行同步。浏览器不依赖 CDN。

## 全 3D 判断与资产任务

技术路线可行，当前不属于全 3D 角色版本。应先制作一名角色、三套衣服、一套动作和一轮完整结算，再扩展角色库。

| 部分 | 需要的交付 | 行为 |
| --- | --- | --- |
| 角色 | 授权可用 GLB/VRM、统一骨骼、材质、LOD | 牌桌与写真共享角色外形 |
| 服装 | 同骨骼蒙皮网格、身体遮罩、配饰绑定 | 真正换装，避免穿模 |
| 动作 | 待机/出牌/不出/输赢/转身/舞蹈 clip | 服务端事件驱动，平滑混合 |
| 表情 | 眨眼/视线/喜悦/思考/失落 morph | 主动选择表情，未来接授权语音嘴型 |
| 镜头 | 稳定牌桌机位、特写、舞台、摄影范围 | 关键牌面可读，演出可跳过 |
| 动态 | 有限头发/裙摆骨骼辅助 | 按性能分档，避免手机实时全布料 |
| 美术 | 角色比例/材质/轮廓光/色调统一规范 | 先统一风格，再增加后期 |

暂定目标为中档手机 30 fps、桌面 60 fps；需要角色与视频同时运行后的真机测试，当前原型不能证明该指标。Three.js + three-vrm 可沿用现有网页与规则服务，不必为了场景迁移重写服务端。

## 2026-10-04：纸牌细节与出牌交互

- 新增原创矢量牌面模块 `playing-card-art.js`：普通牌按点数排布花色，J/Q/K 使用几何纹章，大小王使用黑红星章及中文标识；SVG 手牌和 Canvas 纹理共享同一布局数据，不引入竞品素材。
- 桌面牌使用实际圆角挤出几何体与薄纸侧边。出牌从玩家或对应对手方向进入，逐张错开 18ms，单张落牌 420ms；关闭动态时直接显示最终状态。
- 十张顺子的桌面宽度限制在人物姓名/身份栏之间；手机每行最多七张，保持牌的等比尺寸，避免横向压扁。牌型标签按三维机位投影定位。
- 修复抬起的手牌挡住下一张牌点击区域的问题；保持鼠标拖选、逐张点击和键盘焦点轮廓。大小王增加明确的无障碍名称。
- 修复 3D 不可用时，新增 SVG 装饰可能挤占标准手牌布局的问题；装饰只在成功挂载 3D 时显示。
- 验证覆盖：原三项 WebGL/音频/拖选/手机用例，以及真实种子牌局逐张选出十张顺子、服务端接受、桌面/手机分行、身份栏遮挡检查、静止停止渲染。新增用例实际发现并修复相邻牌点击阻挡；录像依赖缺失已补齐，录像通过 `DRESS_CAPTURE_VIDEO=1` 按需开启，不作为普通测试的必需依赖。

## 2026-10-04：修复 PC 出牌区纵向压扁

用户实机反馈成立：此前虽然几何体保持 .95×1.35 的长宽比，但牌面平铺桌面，低角度相机使其屏幕高度缩短约一半；检查世界尺寸不能代表玩家看到的比例。

PC 出牌区现改为面向相机显示，保持等比缩放与入场方向；沿视线移动，避免牌面下半部分穿入桌面。短窗口按操作按钮位置上移出牌区。标签从实际投影边界定位。桌面场景透视保留。

验证改为测量实际投影后的两条牌边，宽高比目标为 .95/1.35（约 0.704），误差须小于 0.015；覆盖 1280×720、1440×900、1920×1080，同时验证十张顺子不遮挡角色身份栏和手牌操作区。4 项专项浏览器测试全部通过，87 模块语法检查通过。修复仍在 PR #1，未上线。

## 2026-10-04：中央错落牌堆

按用户要求，把 PC 出牌从横向整齐排列改为集中在桌面中央的小范围叠牌；多张牌按数量分成紧凑的错位扇形行，单张与对子保留轻微旋转。每张牌的偏移和角度由本局 ID、牌值、出牌座位固定生成，重绘或切换主题不会重新随机抖动。手机保留窄屏分行并增加较小的角度与位置差异。

PC 牌面使用浅倾斜和等比缩放，在自然错落与角标可读之间取折中；未恢复此前低机位导致的严重纵向压扁。遮叠深度与牌面所在浅平面一致，再施加逐张层差，避免后一行角标被前一行盖住。局部软阴影替换 PC 卡牌的长方向阴影。入场按实际出牌方向，逐张间隔 24ms，560ms 内完成轻抛、短滑和停稳；减少动态时直接落定。属于美术编排动画，不是刚体物理模拟。

验证：4 项专项浏览器用例，实际选出并打出十张顺子；1280×720、1440×900、1920×1080 检查实际投影牌边比例在 0.69–0.79、每张牌左上角标未被其他牌遮挡、牌堆宽度小于视口 40%、不遮挡身份栏和手牌操作区。继续覆盖手机出牌、拖选、音频、切换主题资源复用与闲置停止渲染。静态语法与构建检查通过。截图和录像为实际运行，录像无声；仍在草稿 PR，未部署线上。
