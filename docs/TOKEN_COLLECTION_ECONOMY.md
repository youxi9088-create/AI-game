# Token 与收藏经济规则（2026-10-06）

本次实现替代旧版「开局扣 1、按倍率输赢、每次胜利免费解锁或升级」规则。目标是让对局提供收入，收藏与卡面成长提供明确消费目标，阶段奖励支持下一次选择。Token 仅用于游戏内外观，不可购买、转赠或提现，无现金价值。

## 收入与消费

| 行为 | Token / 条件 |
| --- | --- |
| 新存档初始余额 | 20；已有存档余额原样保留 |
| 开局、流局重发 | 免费；0 余额也可开局 |
| 完成胜局（含农民队友获胜） | +8 |
| 完成负局 | +2 |
| 中途退出、仅创建新局 | 不发奖励 |
| 首胜赠卡 | 首次胜利且尚无卡牌时赠 1 张，可在该牌友目录中换选；这是一次性的胜场门槛例外 |
| 每位牌友目录第 1–2 款 | 24，累计 1 胜后可购买 |
| 第 3–5 款 | 40，累计 3 胜后可购买 |
| 第 6 款起 | 64，累计 6 胜后可购买 |
| Lv.1 → Lv.2 → Lv.3 → Lv.4 → Lv.5 | 分别消耗 12 / 24 / 40 / 60，纯外观升级 |
| 集齐不同款式 1 / 3 / 6 款 | 自动返还 4 / 8 / 12，每档一次 |

倍率、炸弹、春天和地主身份仍展示牌局表现，不放大 Token 收入。胜场与羁绊仍由服务端记录。后续胜局可回看已拥有服装并创作写真，但不会免费增加卡牌或等级；没有已拥有服装时引导进入写真馆，解锁后可回来为该场胜利定格。

新玩家示例：初始 20 → 首胜 +8、收藏奖励 +4，余额 32 → 花 24 自选第二张，剩 8 → 再赢一局余额 16 → 花 12 将喜欢的卡升至 Lv.2，剩 4。玩家也可以继续攒币解锁新卡。升级和定格不增加不同款式数，不能重复触发里程碑。返还金额低于新增卡牌的购买成本。

价格按每位牌友服务端目录顺序确定。后续内容请追加目录，不要随意重排旧条目以免旧卡价格变化。这些数值是首版调参起点，并非已经过留存数据验证。当前内容全部集齐且满级后，余额保留供后续内容使用，没有无限付费升级或强制耗币；有限内容不能宣称形成无限期稳定的经济系统。

## 界面与交易

- 写真馆显示余额、完整规则、每张卡的确定价格、下一级、胜场门槛或差额，不能购买时禁用按钮。
- 点击带明确金额的解锁/升级按钮即交易；等待期间禁用其他交易按钮。成功显示支出、里程碑返还与最终余额，播放收藏音效。
- 前端只提交卡 ID、预期等级、预期价格和幂等键；服务端重新查目录、门槛与余额。旧报价拒绝执行。
- 首胜赠卡可以在演出前换选；购买任意卡或升级会确认当前赠卡，禁止之后换选撤销付费升级。
- 幂等键和交易结果随存档保留。相同交易重试不重复收费，同键换参数拒绝。重复新请求使用旧等级也被拒绝。
- 手机写真馆取消旧版 1024px 最小宽度，导航、规则、筛选和两列卡牌适配窄屏。本次没有重做其他页面。

## 存档与发布

生产已有钱包 v1、画廊 v1/v2 在启动时一并读取验证，再写入钱包 v2。新钱包包含余额、完整账本、卡牌、收藏进度、里程碑与购买幂等记录，临时文件写完后原子重命名。以后以钱包为权威；原画廊文件保留为迁移前备份，不再双写。仅配置 galleryPath 的测试/本地实例使用该文件保存同样的完整账号数据。

写盘失败时回滚内存余额、卡牌、账本、收藏奖励、购买命令和当前牌局。原子提交避免两个文件一个扣款成功、另一个发卡失败。不可读或格式错误的旧档直接报错，不创建空收藏覆盖。原子重命名并不等于支持多进程并发写入。

部署前备份原钱包与画廊，保留现有 Token 收据密钥。回退旧程序必须同步恢复同一时间点的两份备份，旧程序不支持钱包 v2。当前仍是原项目单 player / 单服务进程模型，不包含真实多用户账户隔离或多进程锁。此提交未部署到 yyxx101.online。
