## 点数字形大小不一修复（14:00，0.7.2）

- 根因：AI 生成的 13 张字形图墨迹占比随机偏差（78%~88%），CSS 统一框裁剪后视觉大小仍随图片内容浮动。
- 修复：normalizeGlyphScales()——canvas 512px 画布测量墨迹高度（亮度阈值 245），按 85% 基线算 scale（clamp 0.8~1.3），存 item.glyphScale + glyphScaleVersion=2；cardHtml 内联 calc(var(--glyph-size)*scale) 渲染；触发点=applyTheme 预载流程 + 页面启动当前主题。
- 基准尺寸演变：1.85em（42.9px，用户：太大）→ **1.15em（26.7px，对标内置主题文字数字观感/用户接受过的 26×24 基准）**，用 CSS 变量 --glyph-size 统一控制。实测极差 3.2px。
- 附带发现并修复：styles.css 残留旧规则 `.corner b img.rank-glyph { width:26px; height:24px; object-fit:contain }`（line 153，压缩主体里，覆盖了我以为加过的 1.85em cover——实际从未写上）。
- 教训：调试 DOM 时 verify-render.mjs（完整用户路径）可靠，debug-glyph.mjs 的短等待会读不到 applyTheme 结果（preload+normalize 需数秒）；改 CSS 前先 grep 同选择器的所有规则（压缩单行文件里容易有重复规则）；**用户要"大小一致"时要先问对标基准（内置主题），不要自己发明尺寸**。
