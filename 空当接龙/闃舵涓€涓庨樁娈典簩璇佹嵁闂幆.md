## 输入与边界

- 产品需求：技术设计文档 V1.0 与用户后续修正。
- 不可回退修正：牌面被遮挡即核心玩法失败；自由单元取回不得残留；新局与重置必须不同；合法连续牌组不限搬运张数。
- 方法参考：《思考复盘-01-游戏MVP验证闭环》用于“问题卡—事实—玩家影响—成熟方案—结论—最小真实验证”；《思考复盘-02-UGC自动化工作流》用于区分“请求已发、任务已建、文件已取、可实际应用”，并要求刷新恢复、父任务完成条件和失败下一步。
- 本轮闸门：只完成并汇报阶段一、二；阶段三真实 Provider 不因适配代码存在而算完成。

## 阶段一：核心可玩切片

### 玩家体验问题

玩家的核心动作是读取牌面关系并移动。若被覆盖牌的点数不可见、连续组只选中却落不下、自由单元产生复制牌，或新局沿用旧状态，玩家无法建立规则信任。

### 结论包

- 规则：Microsoft 兼容编号发牌；连续组异色递减、目标合法即无限张数整体移动。
- 状态：新局、重置、撤销、重做、刷新、自由单元取回、停滞和胜利均有明确转移。
- 操作：点击、拖拽、双击、键盘 Enter/Space 与方向键；非法输入和非法移动给出原因与恢复方向。
- 可读性：桌面牌列扇形 48px，较窄桌面 44px，左上角点数与花色不被下一张牌覆盖。

### 验证证据

- Node：规则/API 共 26 项全过；其中含 100 个编号完整性、无限连续组、自由单元不残留、非法移动不变性、50 次撤销与胜利。
- Chrome E2E：18 项全过；其中含编号 7 多牌路径、六步刷新恢复、新局/重置、胜利双出口、非法编号恢复，以及两套已验收主题的加载、应用和刷新持久化。
- 视口：1280×720 与 3840×2160 几何检查均为 52 张、0 个被下一张遮住的左上角、document 无横向溢出。

阶段结论：**PASS（本地 Chrome 目标环境）**。

## 阶段二：UI/UE 与真实表现

### 玩家体验问题

原界面把牌桌做成了管理工具：同色块、弱层级、密集导航和过多空白削弱了游戏感；主题资源即使存在于数据中，也可能因 URL/CSS 错误没有真实渲染。

### 采用并适配的成熟方案

- `game-ui-icons`：采用一致的 20px 线性 SVG 图标和相同几何轮廓的 normal/hover/active/focus 状态；牌面花色仍用固定字符，不让生成素材承载规则信息。
- `navigation-design`：玩家端导航使用语义链接、当前位置和浏览器历史；工坊以“首页 / 主题工坊”定位并提供返回牌桌。
- `web-design-guidelines`：44px 关键目标、可见焦点、skip link、标签、`aria-live`、减少动态效果和破坏性操作确认。
- `imagegen`：只生成低干扰背景和牌背两个代表性真实样本，保留原始生成文件并复制到项目资产目录。

首次截图复核发现内联 style 中的双引号截断了 `url(...)`，导致资源“已登记但未渲染”。修复为安全单引号 URL 后重新截图，背景和牌背均实际出现。这个缺陷证明阶段二必须看真实页面，不能只查 manifest 或接口结果。

### 验证证据

- 文件门禁：运行时读取两项二进制，核对实际字节、SHA-256、审核状态和总包体 5,338,817 < 20MB。
- 应用门禁：图片先加载并 decode，再提交主题；损坏资源 E2E 验证回滚旧主题且牌局不变。
- 页面门禁：首页、牌桌、工坊、主题库四个桌面截图逐页人工复核；本轮按用户决定不把移动端纳入阶段验收范围。
- 交互门禁：导航历史、44px 开始游戏目标、焦点 outline、真实资源 HTTP 加载均有 E2E。
- 规范扫描：无 `transition: all`、无 `outline: none`；输入具备 label/name，异步状态通过 live region 暴露。

阶段结论：**PASS（本地桌面 Chrome，1280 / 1440 / 4K）**。
